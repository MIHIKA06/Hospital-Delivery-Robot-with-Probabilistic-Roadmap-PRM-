# Hospital Delivery Robot with Probabilistic Roadmap (PRM)

CSAI4014 AISR, Project P05, Group G06, Batch B1.
Platform: CoppeliaSim (OMPL plugin) + Python command-line client via the ZeroMQ remote API.

Building a PRM over a hospital floor plan and planning routes between the wards and the pharmacy. Delivery orders are sent to the robot from a Python command-line client.

### Testing with CoppeliaSim (tested with CoppeliaSim Edu 4.10, macOS arm64)

1. Start CoppeliaSim. The ZeroMQ remote API server starts automatically on port 23000.
2. Open `scene/client_test.ttt`, or build it with `python3 tools/build_test_scene.py`. It contains a Pioneer P3-DX with its demo script removed and one `/loc_<name>` dummy per location.
3. Run `python3 -m client`. Orders now move the robot in the simulator.

`scene/client_test.ttt` is only for testing the client. For the real hospital, open `scene/hospital.ttt` instead (see below).

Shell commands: `deliver <pickup> <dropoff> [--urgent] [--item NAME]`, `status`, `queue`,
`history`, `cancel <id>`, `stop` (emergency stop), `resume`, `block <x0> <y0> <x1> <y1>` (mark an area blocked; the PRM re-plans around it), `locations`, `wait`, `quit`.

Each finished order is appended to `results/order_log.csv` with wait time, run time, planning time and path length.

## PRM planner (`planner/`)

- `hospital_map.py` is the 12 m x 12 m floor plan: pharmacy, lab, 3 wards, ICU, corridor, furniture and 1.0 m doors. **Sumit's CoppeliaSim scene must be built from this map.**
- `prm.py` covers the learning phase (sampling plus k-nearest connection, k = 10, max edge 3 m) and the query phase (A*, then shortcut smoothing). The robot is a disc of radius 0.30 m, and obstacles are inflated by that radius.
- It has three samplers: `uniform`, `bridge` (the bridge test of Hsu et al.) and `door` (the default). The door sampler seeds nodes in and beside each doorway.
- `add_obstacle` / `block` remove the roadmap nodes and edges a new obstacle invalidates, without rebuilding the roadmap.
- `python3 -m planner.test_prm` runs the sanity tests.
- `python3 -m planner.plot_roadmap [--sampler uniform|bridge|door] [--block x0 y0 x1 y1]` writes `results/fig_roadmap_*.png`.

First measurements: all 72 ordered location pairs, 10 seeds per setting.

| Sampler | n = 300, mean success | Seeds with 100% of pairs connected |
|---|---|---|
| uniform | 53.9% | 0/10 |
| bridge | 83.3% | 5/10 |
| door | 100% (also at n = 100) | 10/10 |

Query time is under 1 ms per route, and building the roadmap takes about 30 ms.

## Hospital scene and controller (`scene/`, `controller/`)

Sumit could not run CoppeliaSim on his laptop, so Mihika built this module on her machine. It was tested with CoppeliaSim Edu 4.10 on macOS arm64.

- **`scene/hospital.ttt`** is generated by `python3 tools/build_hospital_scene.py` straight from `planner/hospital_map.py`, so the simulator and the PRM always share one floor plan. Walls and furniture are static, respondable cuboids, so the robot really collides with them. Each room has a coloured floor tile. The Pioneer P3-DX `/PioneerP3DX` starts at home with its demo script removed. There is one `/loc_<name>` dummy and blue marker per location, and a 13 m x 13 m floor slab (the default floor is only 5 m x 5 m, and the robot drove off its edge).
- **`controller/controller.py`** provides `follow(sim, robot_handle, path, should_stop)`. It follows the path segment by segment, aiming at a carrot point 0.35 m ahead on the *current* segment, so it does not cut corners in the narrow doors. A PID on the heading error gives the turn rate. The robot slows down when misaligned and turns in place when the error exceeds 50°. (v, w) is converted to wheel speeds with the measured geometry (r = 0.0975 m, track = 0.331 m). The controller runs in stepping mode at 20 Hz of simulation time, played back in real time. It aborts on an emergency stop, after 8 s with no progress, or when more than 0.8 m off the path. `controller.last_stats` holds the RMS and maximum cross-track error and the final position error of the last run.
- `python3 -m controller.test_controller` is an offline test (no simulator). It runs all 72 location pairs on an ideal differential-drive model.
- `python3 tools/test_controller_sim.py [--fast]` drives a 9-leg tour in CoppeliaSim and prints the tracking error of each leg.
- `python3 tools/snapshot.py [--top] --out results/fig_scene_*.png` renders the open scene to a PNG for the report.

CoppeliaSim tour (`test_controller_sim.py --fast`, door sampler): all 9 legs reached the goal. RMS cross-track error was 0.022–0.035 m, maximum 0.14 m (at corners), and final position error under 0.10 m. The full `examples_orders.txt` batch also ran in the simulator: all 5 orders were done, and the urgent ones were served first.

## Baseline and experiments

- `baseline/rrt.py` is a single-query RRT that uses the same map and collision checks as the PRM. Run the client with it using `python3 -m client --planner rrt`.
- `python3 -m client --fifo` serves orders first-come-first-served. This is the baseline for the priority experiment.
- `python3 -m experiments.run_experiments` runs E1-E5 and writes `results/E*.json` (about 30 s). `python3 -m experiments.make_figures` draws the figures.
- E6 (CoppeliaSim tour, client orders, emergency stop) is in `results/E6_coppeliasim.json`, measured with `tools/test_controller_sim.py --fast` and the client.

| Experiment | Main result |
|---|---|
| E1 samplers | door-seeded: 100% of 72 routes from n = 100; uniform 54%, bridge 83% at n = 300 |
| E2 PRM vs RRT | 0.37 ms vs 43.6 ms per route; 200 orders 0.11 s vs 9.3 s; PRM paths 4% shorter |
| E3 dispatch | urgent orders wait 52 / 79 / 88% less than FCFS at low / medium / high load; normal orders wait longer |
| E4 controller | 72/72 routes, mean RMS cross-track error 1.8 cm (also with noise and slip) |
| E5 blocked corridor | 72/72 routes after local repair, about 3 ms vs 27 ms for a full rebuild |
| E6 CoppeliaSim | 9/9 tour legs, RMS 2.2-3.5 cm, final error < 0.10 m; emergency stop 0.06-0.09 s |

## Interfaces between modules

- **`planner/prm.py`** must provide `plan(start, goal) -> list[(x, y)] | None`.
- **`controller/controller.py`** must provide `follow(sim, robot_handle, path, should_stop) -> bool`.
- **Scene**: the robot is named `/PioneerP3DX`. Optional dummies `/loc_pharmacy`, `/loc_ward1`, ... set the location coordinates. Otherwise the client uses `client/config.py`.

Until those files exist, the client falls back to a straight-line planner and a kinematic follower, so it always runs.
